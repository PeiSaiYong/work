Minmed Digital Name Cards

A digital name card for every Minmed staff member, managed centrally. Admins create and change every card. Staff sign in only to see their card, add a name or alias to their link and download their QR code. Anyone with a card's link can open it, but nobody can find it on Google.

Based on Technical Specification draft 0.2 (15/10/2026) and your decisions on 16/10/2026. Names, numbers, codes and QR codes in the examples are made up. Updated 16/10/2026.

Bot protection (CAPTCHA)

Purpose: slow down bots that copy cards in bulk. Random links and hiding from search stop people finding cards; these rules limit how fast anyone can open them. A CAPTCHA can't stop a person, or a bot that pays a solving service, from copying a card they can already open.

RuleWhat's countedLimitThenStatus
Rule 1

Based on industry standards and research

Each rule follows published guidance from OWASP (a web security nonprofit), Cloudflare and Google.

Industry practiceSourceUsed in
Use a CAPTCHA only as a step-up for suspicious traffic, not as the main defence. None of the sources suggests checking every Nth visitor: that would interrupt 1 in 5 real people, while a bot just tries again.OWASPRules 1 and 3, instead of “every 5th visitor”
Limit by more than the IP address. For example, count all requests to one page, whoever sends them.OWASP, CloudflareRule 3
Count in rolling windows, not fixed ones, so bursts can't hide at the edges.OWASPAll rules
A pass lasts 30 minutes by default; 15 to 45 minutes is recommended.CloudflareRule 2
Keep limits in place after a CAPTCHA is passed.OWASPRule 4
Against scraping, use two limits per IP: 10 requests in 2 minutes, then 20 in 5 minutes.CloudflareRule 4's limit
Prefer managed checks that only ask a person to click when needed.CloudflareTurnstile in Managed mode
Run the checks without acting first, then set the limits from real traffic.Google, CloudflareThe first 2 weeks record only

The numbers are starting points. Rule 4's limit matches Cloudflare's example; rule 3's is our estimate for a name card. Both get checked during the record-only weeks.

  • Managed mode: Turnstile decides whether to show a checkbox. Most people never see it, and there are no picture puzzles.
  • Shared networks: office Wi-Fi, events and mobile data put many people behind one IP address, so they meet rule 1 sooner. So does one person who opens a card, saves it and reloads twice. In Managed mode, most still pass without clicking.
  • Server-side: the card page asks a backend function for the card. When a check is needed, no card details are sent until Cloudflare confirms the token.
  • Launch Confirmed: for the first 2 weeks the rules only record. Compare them with real traffic, then switch them on.

Sources: OWASP bot management, Cloudflare rate limiting best practices, Cloudflare challenge passage, Cloudflare challenge types, Google reCAPTCHA v3, Turnstile widget modes and server-side validation.

Links and privacy

  • Link format: me.minmed.sg/card/{code}, or me.minmed.sg/card/{alias}/{code} once the staff member adds a name or alias. For example me.minmed.sg/card/qB8Rh9sTxKuaSF3YkGmD2w and me.minmed.sg/card/Alex-Tan/qB8Rh9sTxKuaSF3YkGmD2w. The code has no name, initials or counting numbers. The /card/ prefix keeps clear of Base44's own addresses.
  • The code Confirmed: 22 random letters and numbers, made by the server with a secure random generator (CSPRNG) and never reused. That's about 131 bits of randomness, above the 128-bit minimum in the standard below.
  • The alias: optional and chosen by the staff member: letters, numbers and hyphens, 2 to 30 characters. It adds no security; the code alone keeps the link unguessable. A link with an alias can be found by searching for that alias.
  • Both parts are checked: the code must belong to a card, and the alias must be the card's current one, or absent when none is set. Anything else shows “No card found” and counts towards rule 1.
  • The link changes only when the alias is set, changed or cleared, or a Super admin issues a new code. Name and designation edits keep the same link.
  • An alias change ends the old link: links already sent, printed QR codes and Apple Wallet passes made from it show “No card found”. The Google Wallet pass updates itself and a new card email goes out.
  • Every public address uses the same random code: the card page, contact file, card image and Google Wallet pass. Never a counting number, so nobody can fetch cards by counting.
  • Hidden from Google, twice over: no list of cards anywhere (no sitemap entries, no staff directory, the home address redirects to minmed.sg), and every card page, image and contact file tells search engines not to index it. On Base44 that means the page's “Search visibility” switch plus a noindex header on files from backend functions, checked after every publish. Don't block card addresses in robots.txt: Google then can't see the “don't index” instruction and may still list a link someone posted elsewhere.
  • If a link is misused: a Super admin issues a new code. The old link then shows “No card found”. An admin can also clear an offensive alias.
  • Bots: see section 8.

Based on industry standards and research

Random strings meant to be unguessable need a secure random generator and at least 128 bits of randomness. Each bit doubles the number of possible codes.OWASP ASVS 5.022 characters
